# Dashboard House UI evidence

Generated by `tools/ux-dashboard-capture.mjs` against `src/dashboard.html`.

This is the primary delivered UI. Every tab was rendered and reviewed at
375 / 768 / 1280 for loading, empty, error, success and disabled.

Dedicated CSS state classes (grep targets):
`table-msg-loading`, `table-msg-empty`, `table-msg-error`, `table-msg-success`,
`house-state-loading`, `house-state-empty`, `house-state-error`,
`house-state-success`, `house-state-disabled`,
`house-banner-success`, `house-banner-error`, `house-banner-disabled`.

Disabled is **not** loading. Capture hangs the in-flight request only for
loading (and for Kill Switch trigger / Algo enable / Backtest run, which
use different copy). Live disabled is a symbol-change in flight on an
already-loaded book. Orders / Positions / Securities disable the primary
control on loaded data with a warning `house-banner-disabled`. The capture
script fails if any loading/disabled PNG pair is byte-identical or shares
a banner title.

No kdb-counts panel was added. Live / History remain anti-oracles for
`orderbook_levels` / `trades`. The kdb oracle is still `fix_console` option 1
(see `docs/ux-kdb-persistence/`).
